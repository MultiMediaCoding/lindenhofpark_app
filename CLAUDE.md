# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Flutter app (German UI) for the Lindenhofpark: an interactive map of trees and historical places, with detail sheets, a searchable/filterable list, and a licenses screen. Requires Dart ^3.13 / Flutter >=3.47. Targets iOS primarily (also has android/web/desktop scaffolding).

## Commands

- `flutter pub get` — install dependencies
- `flutter run` — run the app
- `flutter analyze` — lint (`flutter_lints`; platform folders and `build/` are excluded)
- `flutter test` — run all tests; single file: `flutter test test/map_objects_test.dart`
- `spider build` — regenerate `lib/resources/*.dart` asset constants (config in `spider.yaml`)

## Architecture

Feature-folder layout under `lib/` (`Home`, `Map`, `PlacesList`, `PlaceDetails`, `BiologicalFacts`, `Licenses`, `Common`), each split into `model` / `view` / `view_model` (plus `service`). State uses `provider` with `ChangeNotifier` view models (e.g. `MapViewModel`). Entry: `main.dart` (portrait only; loads the tree catalog) → `HomeView` → `MapView`.

### Data: park catalog + hand-written content

- `assets/map3d/data.js` is the single source for the 476 trees of the GTL Baumkataster (position in metres from the park origin, species, size, age stage, parcel). The 3D scene draws from it and `PlaceDetails/model/trees/tree_catalog.dart` parses the same file into `ParkTree`s (`loadTreeCatalog()` runs in `main`).
- Hand-written tree content (`trees.dart`: photo, origin, planting year, `BiologicalFact`s) is linked to catalog trees by plaque id in `curatedTreeIds` (`tree_knowledge.dart`). `TreeKnowledge` merges both: the linked tree shows everything, other trees of the same species show the species-wide facts and photo (facts for a single specimen are marked `speciesWide: false`), all others show catalog data only.
- Historical places stay hard-coded in `Map/model/map_objects.dart` + `historical_places.dart`, joined **by exact title** (`test/map_objects_test.dart`). Trees are joined by `MapObject.treeId`, never by title (titles repeat). `allMapObjects` = places + all catalog trees.

### Assets

Image/icon paths are generated constants (`TreeImage`, `BiologicalFactImage`, `HistoricalPlaceImage`, `FontAwesomeIcon` in `lib/resources/`) — never hand-write asset paths and don't hand-edit generated files. After adding/removing files in those `assets/...` dirs, run `spider build`.

### Map (3D)

`Map/view/map_view.dart` hosts `assets/map3d/index.html` (three.js, bundled locally for offline use) in a `webview_flutter` WebView. `MapViewModel` calls `ParkApp.*` in the page and receives JSON events on the `ParkChannel` (`ready`, `tree`, `place`, `deselect`, `heading`, `outside`); controls and the detail sheet are Flutter. The chosen tree/place lives in `selectedMapObject` (`Map/view_model/selection.dart`), shared by map taps, the search list and `PlaceSheet`. Trees with hand-written content get a gold star marker (`ParkApp.setStars`); the selected tree turns gold. `index.html` is generated by `python3 tool/build_map3d.py` from the prototype `Lindenhofpark 3D.html` (cuts POV/golf/UI, adds `tool/map3d_api.js`); edit the generated file directly only for small fixes.

### UI conventions

Apple Maps / Liquid Glass look. Map buttons are native `CNButton.icon` (`cupertino_native`). The detail sheet (`PlaceDetails/view/place_sheet.dart`) floats over the map (no route), two detents, content as `GlassCard`s. Its glass background is a native `UIGlassEffect` platform view (`GlassViewFactory` in `ios/Runner/AppDelegate.swift`, wrapped by `Common/view/native_glass.dart`) because Flutter cannot blur the WebView behind it; other platforms get a translucent fallback. The places list is a native Cupertino sheet. Theme uses bundled `Inter` and Material 3 with a green seed.
